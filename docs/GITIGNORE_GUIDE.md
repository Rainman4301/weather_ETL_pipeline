# .gitignore Configuration Guide

---

## Why This Matters

The pipeline uses two `.env` files that contain real secrets — API keys, database passwords, Superset secret keys. These are written at deploy time from GitHub Secrets and must never touch the repository. The `.gitignore` is the last line of defence against accidentally committing them.

---

## What's Ignored and Why

### 🔴 CRITICAL — Secrets

**`airflow/.env`**
Contains `WEATHER_API_KEY`, `WEATHER_API_BASE_URL`, and `WEATHER_API_CITY`. Written by the CI/CD deploy script from GitHub Secrets at runtime.

**`docker/.env`**
Contains 30+ variables including `POSTGRES_PASSWORD`, `DATABASE_PASSWORD`, `SUPERSET_SECRET_KEY`, and `ADMIN_PASSWORD`. Also written by the deploy script at runtime.

**Why:** If either file were committed, anyone with repo access would have live credentials to your database, Superset admin account, and WeatherStack API.

---

### 🟠 HIGH — Generated Data

**`postgres/data/`**
PostgreSQL data directory — written by the `postgres_container` at runtime. Can be gigabytes. Regenerated on every fresh `docker compose up`.

**`dbt/myproject/target/`**
Compiled dbt artifacts — generated by `dbt run` and `dbt compile`. Checked into source control these would create constant spurious diffs.

**`dbt/myproject/logs/`**
dbt execution logs — verbose and runtime-specific.

**`airflow/logs/`**
Airflow task logs — one file per task attempt, grows quickly.

---

### 🟡 MEDIUM — Development Artefacts

**`__pycache__/` and `*.pyc`**
Python bytecode — auto-generated, machine-specific, never needed in the repo.

**`.venv/` and `venv/`**
Virtual environments — if you develop outside Docker, these belong locally only.

**`.pytest_cache/`**
Pytest run cache — regenerated on every test run.

**`.DS_Store`**
macOS metadata files — no value to anyone else.

**`.vscode/` and `.idea/`**
Editor settings — personal to each developer's setup.

## Verifying Nothing Sensitive Is Tracked

```bash
# Check what git currently tracks
git ls-files | grep -E "\.env|postgres/data|target/"
# Should return nothing

# Check what would be committed right now
git status --short | grep -v "^?"
# .env files should not appear

# Confirm a specific file is ignored
git check-ignore -v airflow/.env
# Expected: .gitignore:1:airflow/.env   airflow/.env
```

## If You Accidentally Committed a Secret

Act quickly — assume the secret is compromised the moment it's pushed, even briefly.

```bash
# 1. Remove from git tracking (file stays on disk)
git rm --cached airflow/.env
git rm --cached docker/.env
git commit -m "Remove .env files from git tracking"
git push
```

```bash
# 2. Immediately rotate the exposed credentials:
#    - WEATHER_API_KEY: regenerate at weatherstack.com
#    - SUPERSET_SECRET_KEY: update in GitHub Secrets + re-deploy
#    - POSTGRES_PASSWORD / DATABASE_PASSWORD: update in GitHub Secrets + re-deploy
```

```bash
# 3. If you need to purge from git history entirely:
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch airflow/.env docker/.env" \
  --prune-empty --tag-name-filter cat -- --all
git push origin --force --all
```

> Note: Force-pushing rewrites history. If this is a public or shared repo, notify collaborators.
